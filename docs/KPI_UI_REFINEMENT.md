# KPI UI/UX 고도화 — 2026-10-20

상태: **사용자 배포 승인, 기존 GitHub Pages 반영 준비 중. 실제 화면 전후·모바일·200% 확대·직원 세션 검수는 미실시.** 사용자가 검수 범위를 코드·자동 검사로 한정했다.

- 통합 기준: 운영 main `dc42205a281e31ec9dbe4ec797485101fb128524`. 별도 배포 체크아웃에서 KPI UI 파일만 적용하고, 이미 배포된 빌드업 v4.8·브리지·백엔드 파일은 수정하지 않았다. 원래 작업 폴더의 금융/수집 관련 미커밋 파일도 반영하지 않았다.

## 적용 범위와 진행

- 사용자 확정 범위는 **기존 KPI 화면만**. 선택 홈, 상위 전환 메뉴, 외부 마케팅 허브, 빌드업 원본/iframe은 수정하지 않았다. 로그인·권한·원본 수집·금융 계산·저장 API·DB/트리거 변경 없음.
- 제공한 「디자인 창고 공통 고도화 기준」을 현재 대화의 요구사항으로 적용했다. 문서에 언급된 외부 After 시안은 제공되지 않았으므로 특정 After와의 시각적 동일성을 주장하지 않는다. 별도 디자인 창고나 다른 계정에 기록·업로드하지 않았다.
- 진단 후 원본 `main.jsx`, `styles.css`, `design.css`를 작업영역 진단 폴더 `kpi-ui-before-20261020`에 복사했다. 반복 프리미티브를 분리한 뒤 토큰을 연결·조정했다. 반복되는 덮어쓰기 레이어를 추가하지 않고 KPI 테마 파일을 하나로 정리했다.

## 진단 → 역할 체계

집계 대상은 **기존 KPI 테마 `design.css`**다. 전체 앱의 모든 인라인/차트/레거시 CSS를 센 값은 아니다. 굵기 집계는 @font-face의 지원 범위를 제외한다. 색은 3/6/8자리 hex 표기 자체를 센다.

## 적용 내용

- **PT-01/C-LATIN**: 한글은 기존 Pretendard, 영문·숫자는 Latin unicode 범위의 로컬 Poppins. 400/500/600/700 네 굵기를 합계83,932bytes로 경량화했다. [Google Fonts 공식 Poppins](https://github.com/google/fonts/tree/main/ofl/poppins) 및 공식 CSS 서비스의 Latin subset 사용; OFL 원문을 소스와 `public/licenses/Poppins-OFL.txt`에 포함했다. 라이선스 원문 조회 리비전 `8b0a1d0f5983c89bc2b93f1b5fb55f9e252744b5`. 런타임에 새 글꼴 외부 요청을 추가하지 않는다. 기존 Pretendard CDN 로딩은 그대로다.
- **PT-04/05/15**: 라벨12/필드16, 큰 숫자32/단위16, 모바일 숫자24/단위12. 본문14 기준 섹션20·탭18. 폼48px 버튼·50px 입력, 카드 안 입력은 옅은 면, 바탕 위 입력은 흰 면으로 구분했다.
- **PT-07/08/09/11**: 일반 카드의 선·그림자를 없애고 면으로 구분. 내용 탭은2px 밑줄, 기간 필터는 선택 면, 상태 칩은 작은 라운드로 구분. 기존 primary 호출의 의미는 보존하므로 화면마다 주요 행동이 정확히 하나인지까지 검증한 것은 아니다.
- **G-03/PT-16/19**: 본문 폭1600px 체계, 데스크톱32·태블릿20·모바일16px 인셋. 기본 컨트롤48/50px와 모바일44px 누르는 영역. 계약표 고정 헤더의38/29px 구조는 겹침 방지를 위해 헤더 버튼24px 예외로 보존한다. 표의 본문 편집 컨트롤은 모바일44px로 확장한다.
- **G-20/C-BREAK**: 기존 마케팅→프리미팅→계약 흐름은 유지하고 모바일에서는 한 열과 세로 화살표로 연결. 단계 장식 그라데이션을 제거했다. 화면/지표의 내용·숫자·순서는 바꾸지 않았다.
- **PT-13/접근성**: 섹션 제목은 최대2줄 처리, 포커스 표시·감소된 모션 환경을 지원한다. 모달의 dialog 이름/닫기 레이블을 추가하고 상위 고정 바보다 위에 표시한다. 모달 전체 키보드 포커스 순환/스크린리더 검증은 이번 자동 검사 범위 밖이다.

## 보호한 동작과 예외

- 이벤트·값·disabled/readOnly를 공통 부품으로 그대로 전달한다. UI 모듈은 데이터 요청·세션·저장소를 사용하지 않는다. 페이지 권한·저장 저널·집계·원본 검증·알림의 성공/실패 의미는 변경하지 않았다.
- 잔금 원장의 어두운 면·컨트롤·경고색, 계약표의 스크롤/고정 열/2줄 헤더 위치, 마케팅 표의40px 행 밀도를 유지한다. 색상의 의미를 모르는 차트 계열이나 업무 칩은 임의로 하나의 색으로 합치지 않는다.
- 공통 UI의 개선이며 모든 화면의 개별 부품/버튼 수/색 대비/키보드 흐름을 끝낸 전체 접근성 감사는 아니다.
