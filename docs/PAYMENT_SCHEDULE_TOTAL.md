# 결제 스케줄 총액 단일화

확인일: 2026-09-21 (KST)

## 기준

- 결제 회차가 한 건 이상이면 `총 결제받아야 할 금액`은 회차 금액의 합계다.
- 회차 금액을 추가·수정·삭제하면 합계가 즉시 총액에 반영된다.
- 회차가 있는 동안 상단 총액은 별도로 수정하지 않는다. 총액을 바꾸려면 회차 금액을 수정한다.
- 회차가 없을 때만 상단 총액을 먼저 입력하고 빠른 설정으로 회차를 만든다.
- 계약 완료 전에는 합계를 `expected`, 계약 완료 후에는 `contractAmount`에 저장하되 화면에서는 하나의 총액으로 표시한다.
- `신규 DB`, `TM 진행중`, `프리미팅 확정`이라도 결제 회차가 있으면 합계 금액을 0으로 초기화하지 않는다.

## 영향 범위

- 계약 매출 집계는 계속 `계약 완료` 상태와 계약일 조건을 사용한다. 초기 단계에 결제 스케줄이 있어도 계약 실적으로 계산하지 않는다.
- 입금 완료 여부·입금일·결제수단·메모는 변경하지 않는다.
- 회차가 없는 업체의 기존 총액 입력도 유지한다.
- Supabase 스키마와 Apps Script는 변경하지 않는다. 기존 V3 리드 patch 저장 및 관계형 투영을 그대로 사용한다.

## 회귀 방지

- 600만원 + 800만원 + 600만원 회차는 총액 2,000만원으로 계산한다.
- 초기 단계 재로딩 후에도 회차 합계가 `expected`에 보존된다.
- 계약 완료 상태에서는 회차 합계가 `contractAmount`와 일치한다.
- 회차가 없으면 기존 입력 총액을 유지한다.
