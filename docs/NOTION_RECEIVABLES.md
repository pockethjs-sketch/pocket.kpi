# 노션 선잔금·미납 자료 — 잔금 관리 조회

2026-09-23 기준 노션 `선잔금 및 미납` 데이터 소스(`9a3d2b37-7894-4a53-839d-0eff811d2645`)와 KPI 전용 Supabase `notion_contract_payment_records`를 확인했다. 양쪽 모두 194건이고 Supabase 원본 키도 194개 고유하다. 이번 작업은 이미 이관된 표를 조회하는 기능이며 노션 재이관이나 결제 원장 변경을 수행하지 않는다.

## 화면과 금액 경계

- `잔금 관리 > 운영 잔금 원장`은 기존 계약·결제 회차·실입금의 운영 정본이다.
- `잔금 관리 > 노션 이관 자료`는 별도 읽기 전용 참고 목록이다. `source_key`별로 업체, 계약진행일, 프리, 프로젝트, 선금·잔금 **원문**, 요청 상태, 입금 상태, 특이사항, 노션 원본 링크를 보여준다.
- 노션 선금·잔금은 자유 텍스트이므로 통화 숫자나 입금일로 추정하지 않는다. 원본에 없는 금액은 `—`로 표시하며 0원으로 바꾸지 않는다. 이 목록은 계약액·입금액·미수금·ROAS 및 기존 15분 Sheets 백업에 합산·투영하지 않는다.
- 노션 `요청 상태=완료`와 `입금 상태=입금전`이 동시에 존재한다. 운영 Supabase에서 해당 조합 120건을 확인했으므로 요청 완료를 수금 완료로 취급하지 않는다. 전체 194건 중 업체명 미입력 2건, 계약진행일 미입력 70건, 잔금 원문 미입력 63건이다.
- 회사명만으로 기존 고객과 자동 병합하지 않는다. 후속 통합은 노션 페이지 ID와 계약/업체 고유 ID의 검증된 1:1 매칭, 텍스트 금액의 수동 검수, 입금 증빙을 거친 뒤 별도 승인받는다.

## 보안·API

- 브라우저는 기존 Supabase 직원 세션으로 `kpi-domain-api?action=notion_receivables`만 호출한다. 서버는 활성 조직 membership을 확인하고 `organization_id`로 범위를 좁혀 페이지 단위로 읽는다.
- API는 화면에 필요한 열만 선택하며 `raw_payload`를 보내지 않는다. 직접 브라우저 테이블 접근은 허용하지 않는다. 이관 테이블에 기존 부여돼 있던 `anon`/`authenticated`의 부수 권한도 해당 표에서만 회수한다. 서비스 역할의 기존 이관 권한은 유지한다.
- 조회 실패 시 기존 결제 원장은 유지하고, 마지막 조회 목록이 있으면 그것을 유지하면서 오류를 보여준다. 미로그인·권한 없는 사용자는 기존 앱 진입 및 API 경계에서 차단된다.
- 노션 원본은 별도 이관 프로세스가 갱신한다. 이 화면의 새로고침은 **Supabase 조회만** 수행하며 노션 수집을 실행하지 않는다. 목록의 최종 반영 시각은 DB `updated_at` 중 최댓값이다.

## 검증

- 원본/DB 건수 194/194, Supabase source_key 고유 194, 조직 수 1을 메타데이터만으로 확인했다.
- 로컬 합성 자료 테스트는 요청/입금 독립성, 필터, 외부 링크 안전성, API의 조직 범위·raw payload 제외·페이지네이션을 검증한다.
- 운영 배포 뒤에는 Edge 함수 무인증 HTTP 401, DB 직접 anon 조회 불가, 실제 직원 세션에서 194건 반환, 잔금 원장 합계 불변을 확인해야 한다. 확인하지 못한 항목은 완료로 기록하지 않는다.
