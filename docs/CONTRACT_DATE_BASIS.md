# 계약 총괄 — 미팅/입금 시점 보기

2026-09-18. 화면 계산만 변경하며 기존 날짜·계약금액·입금·시트·DB·백업은 수정하지 않는다.

## 두 기본 보기

- **미팅 일자 기준(기본)**: 현재 계약 완료 + 양수 계약액인 업체를 미팅 날짜로 귀속한다. 여러 CRM type=1 일정이 있으면 한국시간 최초 일자 하나를 사용한다. CRM 일정이 없으면 저장된 프리미팅 완료일 → 프리미팅일 → 예약일 순서다. 계약일·유입일로 대체하지 않는다. 반복 방문 때문에 계약액이 여러 월에 중복 잡히지 않는다.
- **입금 시점 기준**: 결제 회차별 실제 입금 날짜의 금액을 합산한다. 일반 회차는 `paidAt`이 있으면 `amount`, CRM 관리 회차는 `depositAmount`와 `depositAt`(없으면 paidAt)을 사용한다. CRM 일부 입금을 회차 예정 총액으로 부풀리지 않는다. 현재 계약 상태와 관계없이 실제 받은 금액은 포함한다.
- `paidConfirmed`만 있고 실제 날짜가 없는 회차, 결제 회차 없이 `paid`만 남은 구형 금액은 **입금일 미상**에 표시한다. 예정일이나 계약일로 추정하지 않으며 입금 확인을 해제하지 않는다.
- 미팅 날짜 없는 계약도 **미팅일 미상**으로 별도 표시한다. 미상 목록은 선택 고객 유형의 전체 기간이며 월 실적에 포함하지 않는다.

## 화면

- 상단 미팅/입금 전환, 전체/신규/기존, 검색·담당자 필터, 담당자별 시트형 표/전체 목록/월별 비교.
- 입금 표의 금액 열과 합계는 기간 입금액이다. 업체 수는 고유 업체, 회차 수는 실제 입금 이벤트 수다. 전체 목록에서 회차 날짜·금액과 참고 계약 총액을 구분한다.
- 월별 비교는 확인 가능한 날짜가 있는 CRM 기록 전체 월이다. 과거 시트 월 합계에는 미팅일·입금일 근거가 없어 새 두 기준에 섞지 않는다.
- 원래 계약 총괄은 미팅일이 아니라 `contractAt` 기준이었다. 이전 계약일 조회·입금/미수/빌드업 상세·과거 시트 실적은 **기존 계약일·과거 시트 실적** 진입으로 그대로 보존한다. 통합 성과 체크 ROAS·계약일 집계도 그대로다.

## 예시와 검증

- 펩스데이 신규 2,500만원: 저장된 미팅일 8/14 → 미팅 기준 8월 표시. 원본 계약일 9/7은 변경하지 않는다.
- 9월 선금 1,000만원 + 10월 잔금 1,500만원이면 입금 기준 각 월에 각각 합산한다. 계약 총액을 매월 반복 집계하지 않는다.
- 순수 계산 테스트: 분할입금, CRM 일부입금, 미상/잘못된 날짜, 신규/기존, 중복 방문, 월 귀속, 원본 불변. 컴포넌트 렌더링 테스트: 표 머리글·합계·미상 안내·월별 분할·목록 참고 계약액 분리.
