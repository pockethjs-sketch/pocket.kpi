# 마케팅 지표 상세·문의 원천 구분

확인일: 2026-09-17 (Asia/Seoul). 광고·CRM·계약 저장값은 변경하지 않고 화면 계산 내역과 일별 문의 열만 정정한다.

- META / NAVER+GOOGLE 상단 6개 카드(광고비, 유입 DB, CPL, DB→프리미팅, 계약, ROAS)를 누르면 **해당 카드가 집계한 월과 실제 사용된 값**을 표시한다. 월별 광고비·업체별 유입일/채널/프리/계약액/누적 입금을 함께 보여준다. 카드와 상세는 같은 `summaryRows`를 사용한다.
- `유입 DB`는 CRM 리드의 `createdAt` 월과 정규화된 `channel`이 해당 광고 플랫폼에 속하는 업체 수다. 프리미팅·계약·누적 입금도 **이 유입 코호트의 현재 상태**다. 계약은 `contractAt` 또는 `status=계약 완료`; 입금은 결제 회차의 확인액(결제 회차가 없으면 `paid`)을 사용한다.
- 잠재고객 CPL = META 잠재고객 캠페인비 ÷ CRM META 유입 업체 수. 검색 매체 CPL = NAVER+GOOGLE 전체 광고비 ÷ 각 검색 매체 CRM 유입 업체 수. DB→프리미팅 = 방문 완료 업체 ÷ 유입 DB. ROAS = 같은 유입 코호트의 **현재까지 누적 입금 확인액** ÷ 선택 월 전체 광고비 ×100. ROAS는 해당 월 실입금이나 이익률이 아니다. 실제 입금일 없이 H열 확인으로 완료 처리된 금액도 누적액에는 들어간다.
- Supabase `marketingDaily[*].crm`은 현재 `marketing_daily_spend.conversions`에서 만들어지므로 **CRM 문의가 아니라 광고 플랫폼의 전환 수**였다. 반면 카드의 유입 DB는 실제 CRM 업체 수다. 일별 표에서는 CRM 업체의 유입일·채널로 `CRM 문의`를 재계산하고, 광고 API 전환을 `매체 문의전환`에 표시한다. 구형 시트 자료는 기존 `media` 필드를 유지한다. 두 원천은 기여 기간·중복·등록 시점 차이로 꼭 같지 않다.
- 9/17 운영 대조(2026-09 기간): META CRM 유입 40곳, 프리미팅 9곳, 계약 2곳, 잠재고객 캠페인비 8,105,133원, 전체 광고비 9,345,115원, 코호트 누적 입금 8,360,000원, META API 전환 30건. 이 값은 고정하지 않고 이후 운영 데이터에서 재계산한다.
- 광고 API 일별 행이 없는 날짜는 일별 광고·CRM 대조표에 행이 없을 수 있다. 상단 CRM 유입 카드는 저장된 CRM 코호트 전체를 집계한다. 원본 광고 데이터 자체를 가짜 0원 행으로 보강하지 않는다.
- 구형 `marketingMeta.collector`가 없는 현재 직접 수집 구조에서 경고 배너가 `configured=undefined`를 미설정으로 오판했다. 현재 Supabase 공급자별 `sources` 성공·오류 상태를 우선 보도록 고쳤다. 검색 매체의 최신일은 NAVER/GOOGLE 둘 다 있을 때 더 오래된 날짜를 사용한다.
