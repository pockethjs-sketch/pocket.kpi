# 계약·입금 원본 자동점검

이 문서는 기존 `kpi` 6시간 읽기 전용 점검의 계약·입금 검사를 정의한다. 자동 수집·금융 저장·권한·백업·09시 일정은 바꾸지 않는다. 전체 업무 데이터의 정상 판정과 실제 사용자 화면 검증은 별개다.

## 실행

1. 저장소에서 `node scripts/contract-sheet-audit.mjs --sql`을 실행한다. 고정된 사용자 지정 공개 시트 gid0에서 2026-09-01~오늘 KST 원본을 읽는다. 첫 출력 줄은 메타데이터, 나머지는 읽기 전용 대조 SQL이다.
2. 생성된 SQL을 기존 Supabase 관리자 MCP의 execute_sql로 KPI 프로젝트에서 실행한다. SQL에는 고객명·연락처·메모가 아닌 회사/별칭 해시, 날짜·금액·입금률만 들어간다. 직원 API나 Apps Script 보호를 우회하지 않는다.
3. 반환된 audit를 `assessContractAudit`로 판정한다. 원본 조회와 DB 대조는 같은 실행의 결과여야 한다. 결과가30분 넘게 오래됐거나 총수/결과 건수가 다르면 검증 실패다. 접근 실패/로그인 HTML/빈 결과/잘못된 헤더/손상된 날짜는 정상0건이 아니다.
4. sourceGroups/auditedGroups/일치/미해결/입금 대조 미실시, 조회 시각, 원본 해시, DB 리비전, issueFingerprint와 행번호/오류코드만 진단 메타데이터에 보관한다. 원본 CSV·업체명·메모·인증정보를 저장/출력하지 않는다.

## 기준

- H 지급 확인의 정확한 체크는100%, 백분율은 누적 입금률이다. O 별도가와 기존 VAT 파서를 재사용한다. I 입금확인 업로드만으로 지급 완료를 만들지 않는다. 미확인은0원이 아니다.
- 정규화/괄호 별칭과 계약일로 대조한다. 동명·복수 계약·날짜 충돌은 검토 대상으로 남긴다. 다른 날짜 계약들의 합계를 한 기존 계약에 비교하거나 덮어쓰지 않는다.
- 계약 상태/날짜/총액, 회차 합계/확인액, 관계형 계약/입금 원장과 snapshot을 교차 확인한다. 정상 로그/COMPLETED/수동 복원 성공만으로 실제 값 일치를 판단하지 않는다.
- 실제 직원 인증이 있으면 기존 daily_sync_status 읽기로 실행 최신성을 별도 확인한다. 없으면 자동 writer 미검증이다. 관리자 SQL 대조나 합성 테스트는 직원 API/DOM 증거가 아니다.
- 새 차이·악화·새로운 접근 실패·새 조치 필요 때만 알린다. 이미 알려진 확인 필요가 그대로면 계속 미해결로 유지하되 반복 알림하지 않는다. 비교값/알려진 보류 건수를 고정 정상 기준으로 쓰지 않는다.
- 이 도구와 자동점검은 SELECT만 실행한다. 자동 복원/계약 생성/입금 수정/원본 수집/트리거 변경은 하지 않는다.

## 검증 구분

2026-10-16 신규 점검을 실제 공유 원본과 운영 DB로 실행했다.186행/42그룹을 빠짐없이 조회했고 일치21·확인 필요21·입금 대조 미실시17로 전체 정상 아님을 확인했다. 이는 실행 당시 자료 대조 증거이며 자동 writer의 다음 예정 실행이나 실제 직원 브라우저 검증 완료를 의미하지 않는다. 합성 파서·접근 실패·손상 입력·불완전 조회·시간 불일치 회귀 검사는 별도 테스트에 있다.
