### H열 입금 확인 확장 (2026-09-28, Apps Script v61 배포)

- 정확한 `V/v`, `✓/✔/☑/✅`, Google 체크박스 `TRUE`, `입금 완료/지급 완료`는 100%. `50%` 등 0~100% 표기는 VAT 포함 원천 계약액에 곱해 원 단위 반올림한다. 일반 숫자·예정/취소 문구는 완료로 추측하지 않는다. `getDisplayValues`로 퍼센트 표시를 보존한다.

### H열 입금 완료 확인 (2026-09-17 최초 구현, 위 확장 이전)

- H열이 정확히 `✔` 또는 명시적 `입금 완료`/`지급 완료`인 경우만 후보. 보류·리마인드·정기 결제 문구는 완료가 아니다. 원본 계약액은 앞서 확인한 부가세 포함 환산 기준이다.
- 동일 원본/DB 업체 고유 1:1, 원본 계약행 하나, DB 상태 `계약 완료`, 원본 계약액과 DB `contractAmount` 및 유일한 미납 결제 회차 금액이 모두 같아야 한다. 계약액과 결제 회차가 맞지 않거나 기존 부분 입금·복수 계약·CRM 관리 회차·중복 업체는 자동 반영하지 않고 보류 사유를 표시한다.
- 해당 회차에 `paidConfirmed=true`와 누적 `paid=계약액`을 한 DB mutation으로 저장한다. `paidAt`은 빈칸 그대로 둔다. H열에는 실제 입금일이 없으므로 계약일이나 동기화일을 실제 입금일로 만들지 않는다. 수금 현황·미수금은 바뀌지만 입금일 기준 월매출은 별도의 날짜 확인 전까지 바뀌지 않는다.
- `contractSheetPaymentSync`에 원본키·확인 증거 해시·확인시각·실입금일 미상임을 기록하고 동일 mutation의 `contractStatusLogs`에 금액 전후를 남긴다. 이미 완료된 회차는 재반영하지 않는다. 이후 H열이 빈칸으로 바뀌어도 완료를 자동 취소하지 않으며 사람이 원천을 확인해야 한다.
- 계약 자동 보완으로 같은 요청에서 계약액이 새로 채워진 경우에도 위 조건을 충족하면 결제 확인을 하나의 원자 저장으로 묶는다. 원천 시트와 기존 입금 날짜·사용자 메모·기타 회차를 고치지 않는다.

미등록 업체는 기존처럼 `신규업체 생성 / 제외` 미리보기로 처리하며 자동 생성하지 않는다. 이 큐의 기존 업체 대조도 지연될 수 있는 Sheets 원장이 아니라 Supabase 정본을 사용한다.

## 저장 안전장치

- 기존 ScriptLock 및 Supabase base revision/멱등 mutation 경로 사용. 충돌하면 최신 DB로 후보와 패치를 다시 계산한다(최대 3회). 오래된 금액 패치를 그대로 재전송하지 않는다.
- 화면 재조회는 두 도메인의 리비전 일치를 확인하며 Sheets 복구본으로 후퇴하지 않는다.
- 재조회 중 사용자 미저장 변경을 최신 정본에 다시 병합하고 기존 브라우저 저널·저장 큐를 통해 저장한다. 별도 마케팅 값은 보존한다.
- 서버 성공 및 DB 재조회 전에는 성공 표시하지 않는다. HTML 응답·통신 실패 시 기존 값과 마지막 결과를 남기고 실패를 표시한다.
- 보류 목록에 업체명·이유를 표시한다. 사람이 판단할 계약을 임의로 덮어쓰지 않는다.
