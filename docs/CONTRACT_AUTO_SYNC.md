## 원천과 저장 경로

- 읽기 전용 원천: Google Sheet `1vNlj417n1JE0HTOky5FCKS0_Y5daeor7oIok3SXMbss`, `계약 프로세스`, gid 0.

## 자동 처리 대상

1. 시트 계약일 2026-08-01 이후부터 실행 당일까지, 해당 업체의 모든 계약 행이 명시적으로 `신규`.
2. 프리미팅 일정/내방 기록이 있고 상태가 프리미팅 확정·완료, 견적·제안 발송, 계약 완료인 저장 업체.
3. 회사명 또는 괄호 별칭이 정확히 일치하는 1:1 연결. 법인 표기·공백·문장부호 정규화만 사용하며 유사도 추정은 하지 않는다. 복합 업체명(`/` 등)과 중복 매칭은 자동 반영하지 않는다.
4. 대상 업체도 신규여야 한다. 계약일·프로젝트·금액이 유효해야 한다. 복수 계약일·중복 행·추가/반복 계약 의심·금액 불명은 보류한다.

| 항목 | 저장 규칙 |
|---|---|
| 별도가 | 숫자는 만원 단위. 부가세 10% 포함 후 원 단위 반올림. `원` 단위 표기는 직접 환산. `(포함가)` 등 명시 시 추가 VAT 없음 |
| 계약액 | `contractAmount`. 최초에는 비어 있거나 0인 값만 보완. 기존 값이 같으면 허용, 다르면 보류 |
| 계약일 | `contractAt`. 위와 같은 기존 입력 보호 |
| 상태 | `계약 완료`. 계약 수·계약액·ROAS 집계에도 영향 |
| 프로젝트·비고 | `memo`에 `[계약 프로세스 자동연동]` 구획 추가. 기존 사용자 메모는 유지 |
| 빌드업 | 원본 프로젝트에서 확실히 분류되고 기존 필드가 비어 있을 때만 보완 |
| 입금·중도금·잔금 | `payments`, `paid`, 결제계획 및 기존 상세 계약 항목을 수정하지 않음. 계약액이 기존 입금액보다 작으면 보류 |
| 견적·영업담당·내방일 | 기존 `expected`, 담당자, 프리미팅 기록 유지 |
| 동기화 이력 | 리드 `contractSheetSync`에 원본 행·의미 해시·마지막 반영값·시각. `contractStatusLogs`에 `외부 시트 자동 반영`과 전후값 |

이후 원본 값이 바뀌면, 현재 값이 마지막 자동 반영값과 같은 필드만 갱신한다. 사용자가 별도로 수정한 금액·계약일은 덮어쓰지 않는다. 같은 원본 재조회, 행 이동, 입금 체크박스 변경만으로 계약을 다시 적용하지 않는다. 원본 행이 줄거나 삭제되어도 고객 삭제·금액 감소를 전파하지 않는다.

미등록 업체는 기존처럼 `신규업체 생성 / 제외` 미리보기로 처리하며 자동 생성하지 않는다. 이 큐의 기존 업체 대조도 지연될 수 있는 Sheets 원장이 아니라 Supabase 정본을 사용한다.

## 저장 안전장치

- 기존 ScriptLock 및 Supabase base revision/멱등 mutation 경로 사용. 충돌하면 최신 DB로 후보와 패치를 다시 계산한다(최대 3회). 오래된 금액 패치를 그대로 재전송하지 않는다.
- 화면 재조회는 두 도메인의 리비전 일치를 확인하며 Sheets 복구본으로 후퇴하지 않는다.
- 재조회 중 사용자 미저장 변경을 최신 정본에 다시 병합하고 기존 브라우저 저널·저장 큐를 통해 저장한다. 별도 마케팅 값은 보존한다.
- 서버 성공 및 DB 재조회 전에는 성공 표시하지 않는다. HTML 응답·통신 실패 시 기존 값과 마지막 결과를 남기고 실패를 표시한다.
- 보류 목록에 업체명·이유를 표시한다. 사람이 판단할 계약을 임의로 덮어쓰지 않는다.
