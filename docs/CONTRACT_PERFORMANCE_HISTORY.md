# 계약 성과 과거 실적 / 월별 비교

2026-09-15 구현·운영 DB 이관. 이 화면은 읽기 전용이며 계약·잔금 저장을 변경하지 않는다.

## 원천과 범위

- 원천: Google Sheet `10Zx1tNpdnVtTNK4beRBAyLji2X0u63w0QMdcy9EMsZ8`.
- `월별성과`: 2024-01 ~ 2026-06, 30개월의 기재 계약 수·계약액·광고비.
- `월별계약`: 2024-10 ~ 2026-06, 21개월의 업체별 421행, 담당자 그룹 60개.
- 상세가 있는 21개월 모두 상세 계약액 합계 = 원본 추가계약 포함 매출을 검증.
- 원본에 없는 계약 일자·신규/기존·입금액은 생성하지 않는다. 과거 등급(A/B 등), 프로그램 표기를 보존.
- 월 기재 계약 수는 실제 업체 행 수와 다를 수 있다. 둘을 별도 보존하며 화면에서 차이를 표시한다.
- 2024-10~12의 월별성과 금액은 추가계약 포함 합계와 다르므로 월별 비교 계약액은 추가계약 포함 합계를 우선한다. 2024-01~09는 추가계약 포함 여부 미확인.

## 저장과 보안

KPI 전용 Supabase `ilnklntqkdbbtzzbhqrl`의 `contract_history_months`, `contract_history_owners`, `contract_history_details`.
조직/월/원본 셀 또는 열 기준 PK·FK, numeric 금액, RLS 활성화. anon/authenticated 직접 접근 권한 없음.
기존 JWT+앱 토큰 검증을 거친 `kpi-domain-api?action=contract_history`만 조직 제한으로 페이지 단위 조회.
원본 사업 데이터는 GitHub 소스·프런트 번들에 포함하지 않고 DB와 무시된 로컬 artifacts에만 보관.
기존 암호화 DB 백업은 public 업무 테이블을 자동 탐색하므로 세 테이블도 대상이다. 새 백업의 실제 복원 실행은 이번 범위에 포함하지 않았다.

## 화면 / 계산

계약 총괄 → `월별 비교·과거 실적`: 연도/모든 연도, 계약액/계약 수, 기존 전체/신규/기존 필터, 전월 대비, 월 클릭 상세.
과거 월은 시트 보관 실적이 우선이며 같은 월의 CRM 계약은 더하지 않는다. CRM 원본 행은 보존.
원본 분류가 없으면 신규/기존 필터에서 `—`로 표시하고 전체 조회를 안내한다. 상단 기간은 현재 보기용, 월별 비교는 연도 선택을 사용한다.
담당자 계약 수는 상세 행 수, 월 전체 계약 수는 시트 기재 값. 금액·기간 간 비교 기준이 다르거나 전월 자료가 없거나 분모가 0이면 증감률을 계산하지 않는다.
월 중 실적에는 진행 중 표시. 없는 월을 0원으로 채우지 않는다.
월별 상세는 기존 시트형 담당자 표를 재사용하고 원본 셀로 이동한다. 과거 입금/미수금은 계산하지 않는다.

## 재이관 / 복구

`scripts/contract-history-parser.mjs`로 원천 범위를 파싱하고 `scripts/import-contract-history.mjs`로 검산·이관한다.
기본 실행은 dry-run. `--apply`와 인증된 `KPI_SUPABASE_CLI`를 지정해야 운영 DB에 쓴다.
같은 자료 재이관은 ON CONFLICT DO NOTHING + 전체 필드 대조. 달라진 원천은 history_conflict로 전체 롤백하며 자동 덮어쓰지 않는다.
이번 이관은 정기 Sheets 동기화가 아닌 보관 시점 자료다. 원천 변경 시 새 검토·이관 절차가 필요하다.
롤백은 UI/API 추가 부분을 되돌리고 세 보관 테이블을 유지하는 비파괴 방식. 기존 leads/deals/payments를 수정할 필요가 없다.
Apps Script 변경 없음. 신규 migration + domain Edge + 웹 배포가 필요하다.

## 검증
